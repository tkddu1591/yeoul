# 쉬운 모드(Easy Mode) 설계

작성일: 2026-07-15
상태: 사용자 승인된 브레인스토밍 결과

## 1. 목적

AI 도구로 개발하는 일반 사용자(비개발자)는 Git을 어려워한다. 기존 Git GUI도 개발자 용어와 개념을 전제하므로 진입 장벽이 높다. 쉬운 모드는 이런 사용자가 터미널 지식이나 Git 용어 없이도 **저장, 백업, 되돌리기, 실험, 협업**을 안전하게 수행하도록 돕는다.

쉬운 모드는 [제품 비전](../../PRODUCT_VISION.md)의 원칙을 그대로 따른다. 상태를 숨기지 않고, 실행 전 영향을 보여 주고, 복구 경로를 함께 제공한다. 차이는 표현 방식이다.

## 2. 대상 사용자

- AI 코딩 도구로 앱을 만들지만 Git 개념(commit, branch, merge)이 낯선 사람
- "코드가 잘 되던 시점으로 돌아가고 싶다"가 가장 큰 니즈인 사람
- 소규모로 다른 사람과 결과물을 공유·리뷰하고 싶은 사람

## 3. 결정 요약

| 항목 | 결정 |
| --- | --- |
| 작업 범위 | 저장·백업·되돌리기 + 실험 공간(branch) + 협업(PR 전체 리뷰 흐름) |
| 모드 구조 | 듀얼 모드 — 같은 저장소·같은 상태, 언제든 토글 전환 |
| 용어 전략 | 일상어 주 표기 + Git 용어 병기 |
| 메인 화면 | 2패널 — "지금 바뀐 것" + "저장된 역사" |
| 안전 모델 | 보관함(shelve) 자동 보호 + 기간 만료 자동 정리 |
| 충돌 해결 | 하나씩 선택형 기본 + "자세히 보기"로 상세 뷰, 결과 직접 수정 가능 |
| 저장 메시지 | 변경 요약 자동 제안, 사용자 수정 가능 |
| 디자인 | Adobe Spectrum 계열 디자인 시스템 참조, 세련된 데스크톱 앱 품질 |

## 4. 모드 구조

- 하나의 앱에서 **쉬운 모드**와 **개발자 모드**가 공존하고 토글로 즉시 전환한다.
- 두 모드는 같은 Domain·Application 계층을 공유한다. 쉬운 모드는 **UI 계층의 별도 프레젠테이션**이며, 쉬운 모드 전용 Git 로직을 만들지 않는다.
- 쉬운 모드에서 수행한 모든 작업은 개발자 모드(그리고 CLI)에서 표준 Git 상태로 그대로 보인다. 반대도 마찬가지다.
- 쉬운 모드에서 해석할 수 없는 상태(예: bisect 진행 중)를 만나면 추측하지 않고 상태를 설명한 뒤 개발자 모드로 안내한다.

## 5. 메인 화면: 2패널

- 왼쪽 패널 **"지금 바뀐 것"**: 변경 파일 목록. 파일별 변경 종류(수정됨·새 파일·삭제됨)를 표시하고 선택하면 쉬운 diff 뷰를 연다.
- 오른쪽 패널 **"저장된 역사"**: commit 히스토리. 각 항목에서 "이 시점으로 되돌리기", "변경 내용 보기"를 제공한다.
- 상단 액션 바: 저장하기(commit), 백업(push), 되돌리기, 실험 공간(branch), 보관함.
- 개발자 모드와 화면 구조가 유사해 모드 전환 시 이질감을 줄인다.

### 문구 원칙

1. **일상어 + Git 용어 병기.** 예: "저장하기 `commit`", "백업 `push`", "실험 공간 `branch`". 사용자가 자연스럽게 Git 용어를 익혀 개발자 모드 전환, AI 질문, 검색에서 용어 단절이 없게 한다.
2. **관찰 가능한 사실만 말한다.** "파일 5개가 바뀌었어요"(O), "AI가 로그인 화면을 수정했어요"(X). 앱이 알 수 없는 주체·의도를 추측해 말하지 않는다.

### 용어 사전 (초안)

| 쉬운 모드 표기 | Git 개념 |
| --- | --- |
| 저장하기 | commit |
| 백업 | push |
| 최신 받아오기 | pull / fetch |
| 저장된 역사 | commit log |
| 이 시점으로 되돌리기 | restore / reset (보관함 보호 하에) |
| 실험 공간 | branch |
| 실험 공간 합치기 | merge |
| 보관함 | shelf (stash 기반) |
| 리뷰 요청 | pull request |
| 그만두고 원래대로 | abort |

용어 사전은 단일 소스(예: i18n 리소스)로 관리하고 UI 문자열이 임의로 새 용어를 만들지 않는다.

## 6. 안전 모델: 보관함

쉬운 모드의 핵심 보장: **어떤 버튼을 눌러도 작업물이 영구 삭제되지 않는다.**

- 되돌리기, 실험 공간 합치기·전환 등 현재 작업을 덮을 수 있는 동작 전에 저장 안 된 변경을 **자동으로 보관함에 넣고** 진행한다.
- **스마트 병합**: 저장 안 된 변경이 있는 채로 합치기·전환을 실행하면 자동 보관 → 작업 수행 → 보관 항목 자동 복원 순서로 진행한다(IntelliJ smart checkout과 동일한 경험). 복원 중 충돌이 나면 충돌 해결 흐름으로 안내한다.
- 보관함 항목은 기본 30일 뒤 자동 정리한다. 기간은 설정 가능하고, 정리 전에 알린다.
- 보관함은 상단 액션 바에서 항상 접근 가능하다. 각 항목은 생성 계기(예: "되돌리기 전 자동 보관")와 시각을 함께 보여 준다.
- 구현은 Git 표준 메커니즘(stash 또는 임시 ref) 위에 두어 개발자 모드·CLI에서도 접근 가능해야 한다.

## 7. 충돌 해결

2단 구조로 제공한다.

1. **하나씩 선택형(기본)**: 충돌을 한 건씩 카드로 보여 준다. "두 버전이 같은 곳을 다르게 고쳤어요. 어느 쪽을 쓸까요?" — 양쪽 코드를 나란히 보여 주고 한쪽을 선택하면 다음 충돌로 진행한다. 진행 표시(예: 2곳 중 1번째)를 제공한다.
2. **자세히 보기(상세 뷰)**: 양쪽 버전과 "합쳐진 결과"를 한 화면에 배치. 선택이 결과에 즉시 반영되고 **결과를 직접 수정**할 수 있다. 개발자 모드 3-way 편집기의 단순화 버전.

공통 원칙:

- **"그만두고 원래대로 `abort`"** 버튼이 모든 단계에서 항상 보인다.
- 해결 완료 전에는 아무것도 확정되지 않는다. 선택형에서 상세 뷰로 전환해도 이미 한 선택은 유지된다.
- 앱을 종료했다 다시 열어도 진행 상태가 복원된다(기존 비전의 중단 상태 복원 요구와 동일).

## 8. 저장 메시지 자동 제안

- 변경된 파일·내용을 분석해 저장 메시지를 자동 제안한다. 기본은 로컬 규칙 기반(파일 수, 경로, 변경 유형), AI 연동은 선택 옵션.
- 사용자는 제안을 그대로 쓰거나 수정한다. 빈 메시지로 저장하면 제안 문구가 대신 들어간다.
- 제안 로직은 Application 계층에 두고 UI는 결과만 표시한다.

## 9. 협업: 리뷰 흐름 내장

실험 공간 → 백업 → 리뷰 요청(PR) 생성 → 코멘트 확인·답변 → 승인 → 병합까지 앱 안에서 수행한다.

- 기존 비전 문서 11장의 "pull/merge request 연동은 추후 별도 범위" 항목을 이 기획으로 구체화한다.
- 이슈·프로젝트 관리 등 호스팅 서비스의 나머지 기능은 여전히 비목표다.
- 규모가 크므로 쉬운 모드 로드맵의 마지막 단계(E3)로 배치한다.
- 호스팅 API 차이는 기존 Hosting adapter 계층이 흡수한다.

## 10. 디자인 시스템

- **Adobe Spectrum(Spectrum 2) 계열 디자인 시스템을 기준 참조**로 삼는다. 데스크톱 프로덕티비티 앱에 검증된 밀도, 컴포넌트 위계, 접근성 기준을 따른다. 필요 시 동급 품질 시스템(예: Atlassian Design System)을 보조 참조한다.
- 토큰(색·간격·타이포·모서리·그림자)을 먼저 정의하고 컴포넌트는 토큰만 사용한다. 임의 색·임의 간격을 금지한다.
- 한글 타이포그래피는 Pretendard 등 한글 최적화 서체를 우선한다.
- **"AI 생성물처럼 보이는" 관습을 금지한다**: 보라색 그라데이션 남용, 이모지를 아이콘 대용으로 사용, 과도한 glassmorphism, 획일적 카드 나열. 아이콘은 일관된 아이콘 세트(예: Lucide, Phosphor) 하나만 사용한다.
- 위험 동작(되돌리기 확정, 강제 백업)은 색·위치·확인 절차가 시각적으로 구분되어야 한다(비전 문서의 "안전한 기본값과 명시적 위험" 원칙).
- 라이트·다크 테마를 토큰 수준에서 지원한다.

### 시각 언어 우선 (픽토그램)

긴 설명 문구("이 버전", "저 버전", "실험 공간의 변경 사항이…")로 개념을 지시하지 않는다. 핵심 개념마다 **고정된 픽토그램 + 색**을 부여하고 앱 전체에서 일관되게 사용한다.

- 개념별 시각 정체성: 내 작업, 실험 공간, 저장 시점, 보관함, 백업, 충돌 등은 각자 고유 아이콘·색을 갖고 모든 화면(패널, 카드, 타임라인, 충돌 뷰)에서 동일하게 등장한다. 사용자는 문장을 읽지 않고도 "초록 = 내 작업, 보라 = 실험 공간"처럼 시각적으로 추적할 수 있다.
- 구조는 그림으로: 실험 공간 만들기·합치기, 되돌리기 같은 구조 변화는 문장 대신 간단한 다이어그램 픽토그램(두 줄이 갈라지고 합쳐지는 그림 등)으로 먼저 보여 주고 텍스트는 보조한다.
- 텍스트는 짧은 라벨 + 필요 시 확장: 기본 화면은 아이콘 + 한 줄 라벨로 구성하고, 자세한 설명은 툴팁·"자세히 보기"로 미룬다.
- **선택의 결과는 반드시 말로 설명한다.** 픽토그램 우선이 설명 생략을 뜻하지 않는다. 충돌 해결처럼 한쪽을 고르면 다른 쪽이 결과에서 빠지는 선택 화면은 세 층의 설명을 갖춘다: ① 상단 안내문 — 무슨 일이 벌어졌고 무엇을 하면 되는지, ② 각 선택지의 한 줄 의미 — 이 선택이 코드에서 뜻하는 것(예: "버튼을 파란색으로"), ③ 결과 안내 — 선택하면 어떻게 되는지와 "선택하지 않은 쪽도 사라지지 않고 저장된 역사에 남는다"는 안심 문구.
- 접근성: 아이콘·색 단독으로 의미를 전달하지 않는다. 항상 텍스트 라벨 또는 접근성 레이블을 병행하고, 색 구분은 색약 사용자를 고려한 팔레트로 검증한다.

## 11. 로드맵 배치

쉬운 모드는 별도 트랙이 아니라 기존 0~3단계 위에 얹는다. 개발자 모드 기능(엔진)이 먼저 존재해야 해당 쉬운 모드 기능이 얹힌다.

| 쉬운 모드 단계 | 범위 | 의존하는 기존 단계 |
| --- | --- | --- |
| E0 | 2패널 메인, 저장·백업·역사 보기, 메시지 자동 제안 | 0단계 (기반) |
| E1 | 되돌리기 + 보관함, 실험 공간 만들기·합치기 | 1단계 (stash, merge) |
| E2 | 충돌 선택형 + 상세 뷰, 스마트 병합 | 1단계 (충돌 엔진) |
| E3 | 협업 — 리뷰 요청 생성부터 병합까지 | 1·3단계 (호스팅, 다중 계정) |

## 12. 검증 시나리오 추가안

GIT_SCENARIOS.md에 쉬운 모드 시나리오를 추가한다. 초안:

- **E-001 보관함 자동 보호 후 되돌리기**: 저장 안 된 변경이 있는 상태에서 과거 시점으로 되돌리기 → 변경이 보관함에 들어가고, 보관함에서 복원하면 되돌리기 이전 상태를 재현할 수 있다.
- **E-002 스마트 병합 중 앱 종료**: 자동 보관 → 병합 진행 중 앱 강제 종료 → 재실행 시 진행 상태와 보관 항목이 보존되고 안전한 재개·정리 선택지를 제공한다.
- **E-003 모드 전환 일관성**: 쉬운 모드에서 저장·보관·병합 수행 → 개발자 모드와 CLI에서 동일한 Git 상태로 관찰된다. 반대 방향도 동일하다.
- **E-004 충돌 뷰 전환**: 선택형에서 일부 충돌 해결 → 상세 뷰로 전환 → 선택이 유지되고 결과 직접 수정이 반영된다.
- **E-005 보관함 만료**: 보관 항목이 설정 기간을 지나면 정리 예고 후 삭제되고, 기간 내 항목은 복원 가능하다.
- **E-006 해석 불가 상태**: bisect 등 쉬운 모드가 다루지 않는 상태를 만나면 작업 버튼을 추측 제공하지 않고 상태 설명과 개발자 모드 안내를 보여 준다.

각 시나리오는 기존 문서 원칙대로 fixture 저장소, 시작 상태, 행동, 기대, 복구를 갖춘 테스트 명세로 발전시킨다.

## 13. 비목표

- 쉬운 모드 전용 Git 엔진·상태 모델을 따로 만드는 것 (Domain 계층 공유가 원칙)
- Git 상태를 실제와 다르게 보이도록 단순화하는 것 (표현만 쉽게, 의미는 보존)
- 충돌을 사용자 확인 없이 자동 해결하는 것
- 호스팅 서비스의 이슈·프로젝트 관리 기능 복제

## 14. 미해결 질문 (구현 계획 단계에서 결정)
