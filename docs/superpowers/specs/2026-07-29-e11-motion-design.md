# E11 — 모션 체계 설계

2026-07-29 사용자 지시: "사이드바나 diff나 클릭 시에 동작이 애니메이션도 없고 트랜지션도 없고 그냥 다 바로 움직여버리니까 너무 딱딱한 느낌이 든다. 전체적으로 부드러운 앱처럼 만들려면?"

사용자 선택: **세 군데 + 레이아웃 전환**, **E2E는 모션을 켠 채로 돌린다**.

## 실측 배경

이 앱에는 사실상 모션이 없다. 느낌이 아니라 사실이다.

| 항목 | 현황 |
| --- | --- |
| `transition:` 선언 | **1개** — `ui-button`(E9에서 추가) |
| `@keyframes` | **1개** — 확인창 페이드 120ms |
| `prefers-reduced-motion` | **0건** |
| 레이아웃 속성(`height`·`width`·`top`…)에 걸린 transition | **0건** (좋다 — 이 상태를 유지한다) |

가상 스크롤 사용처 **5곳**(`HistoryPanel`·`DiffView`·`ChangesPanel`·`ConflictPanel`·`CommitDetailPanel`).

## 구현 기법 — View Transitions는 쓰지 않는다 (측정 후 기각)

`document.startViewTransition`은 **사용 가능하다**(실제 앱에서 확인: Electron 35.7.5 / Chromium 134.0.6998.205, 기본 전체 문서 전환 **297ms**). 그럼에도 쓰지 않는다:

- React 상태 갱신을 `flushSync`로 감싸야 해서 **렌더링과 애니메이션이 결합**된다. 이 저장소는 `useMemo`·`useCallback`조차 피하고 런타임 최적화에 위임하는 곳이다(전역 규칙).
- 전체 문서를 스냅샷하므로 터미널(xterm)·가상 스크롤이 붙은 화면에서 비용과 부작용을 예측하기 어렵다.
- **CSS만으로 같은 결과가 나온다.** 아래 ⑤가 그 근거다.

기각했다는 사실과 이유를 코드 주석이 아니라 이 스펙에 남긴다(나중에 "왜 안 썼지?"를 막는다).

## ① 모션 토큰

E9가 모서리를 용도 3단으로 정리한 것과 같은 방식. `tokens.css`에 추가한다.

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--motion-fast` | **100ms** | 호버·눌림·포커스 — 손끝에 붙는 피드백 |
| `--motion-base` | **150ms** | 내용 교체 페이드, 등장/퇴장 |
| `--motion-slow` | **240ms** | 크게 움직이는 것(상세 슬롯 열림/닫힘) |
| `--ease-out` | `cubic-bezier(.2, 0, 0, 1)` | 등장·사용자 시작 동작의 기본 |
| `--ease-in-out` | `cubic-bezier(.4, 0, .2, 1)` | 양방향으로 오가는 상태 |

**200ms를 넘기면 부드러운 게 아니라 느린 것**이다. `--motion-slow`만 예외로 두고 그 이상은 만들지 않는다.

## ② 피드백 — 호버·눌림·선택

가장 큰 "살아 있다"는 인상을 만들면서 비용이 사실상 0인 층. 대상: 파일 행·커밋 행·브랜치 행·워크트리 행·탭·메뉴 항목·버튼.

- `transition: background-color, color, border-color` at `--motion-fast` `--ease-out`.
- **`transition: all`을 쓰지 않는다** — 의도치 않은 속성(레이아웃 포함)까지 걸려 원인 추적이 불가능해진다.
- 가상 스크롤 행에도 **이 층은 안전하다**: 색만 바뀌고 레이아웃·위치가 변하지 않으므로 재활용과 충돌하지 않는다.

## ③ 내용 교체 페이드

같은 자리에서 내용만 바뀌는 순간 — diff 파일 전환, 커밋 상세 전환, 리뷰 상세 전환. 눈이 "무엇이 바뀌었는지" 따라갈 시간을 준다.

- 내용 컨테이너에 `key`를 걸어 교체 시 `--motion-base` 동안 `opacity 0→1` + `translateY(3px)→0`.
- **높이는 건드리지 않는다.** 컨테이너 크기는 그대로 두고 안쪽만 페이드한다.
- 3px은 의도적으로 작다. 크게 움직이면 "미끄러진다"는 인상이 되어 오히려 느려 보인다.

## ④ 등장·퇴장

없던 것이 생기는 순간 — 팝오버·다이얼로그·툴팁·알림 배너·FindBar.

- `--motion-base` `--ease-out`, `opacity` + 작은 `translateY`(4px) 또는 `scale(.98)`.
- **퇴장은 넣지 않는다.** React 언마운트에 퇴장 애니메이션을 붙이려면 상태를 하나 더 들고 있어야 하고(`isClosing`), 그 상태가 ESC·외부 클릭·라우팅과 얽혀 버그가 난다. 등장만으로 충분히 부드럽다 — 이건 타협이 아니라 **의도된 비대칭**이다.
- 기존 확인창의 `ui-fade-in`(120ms)을 이 규칙으로 흡수한다.

## ⑤ 레이아웃 전환 (사용자가 요청한 범위)

"레이아웃 전환"을 실제 순간으로 분해하면 넷이고, **셋만 한다.**

| 순간 | 처리 |
| --- | --- |
| **좌측 탭 전환**(변경↔브랜치↔워크트리) | 내용 크로스페이드(③과 같은 기법). **레이아웃은 바뀌지 않는다** — 탭 내용이 같은 상자를 차지하므로 페이드만으로 전환으로 읽힌다 |
| **우측 커밋 상세 슬롯 열림/닫힘** | 진짜 높이 변화다(`layout.css:275` `height: 45%`). `grid-template-rows: 0fr → 1fr` 전환으로 처리한다 — Chromium이 보간하는 몇 안 되는 레이아웃 경로이고 `--motion-slow`를 쓴다. `.app__right`를 flex → grid로 바꿔야 하므로 **기존 배치 무회귀가 이 항목의 최대 위험** |
| **알림 배너 등장** | ④와 동일. 기존 "높이 0 레이어" 구조(E1d)라 시프트가 없다 — 그 성질을 유지한다 |
| **패널 드래그 리사이즈**(E6a) | **하지 않는다.** 드래그는 커서를 1:1로 따라가야 한다. 전환을 걸면 손보다 늦게 와서 "부드럽다"가 아니라 **"굼뜨다"**가 된다. 사용자가 요청한 범위에 들어가지만, 요청의 목적(부드러움)에 반하므로 명시적으로 뺀다 |
| **가상 스크롤 행 추가/제거** | **하지 않는다.** 행이 재활용되므로 등장 애니메이션을 붙이면 스크롤할 때마다 깜빡인다 |

## ⑥ `prefers-reduced-motion`

OS에서 모션 줄이기를 켠 사용자에게는 **전부 꺼진다.** `base.css`에 전역 블록 하나:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

`0`이 아니라 `0.01ms`인 이유: `transitionend`·`animationend`에 의존하는 코드가 있어도 이벤트는 계속 발화한다(현재는 없지만 미래를 막지 않는다).

## 에러·엣지

| 상황 | 처리 |
| --- | --- |
| E2E 106건이 전환 때문에 흔들림 | 사용자 결정대로 **켠 채로 돌린다**. 최장 240ms이고 Playwright 단언은 자동 재시도한다. 흔들리면 고정 대기가 아니라 **단언 타임아웃**을 올린다 |
| `grid-template-rows` 전환이 상세 슬롯 안 가상 스크롤과 충돌 | 열리는 동안 높이가 변하므로 가상 스크롤이 재측정한다. **열림 중 스크롤 위치·행 렌더가 깨지지 않는지 실측 필수** |
| 페이드가 `busy` 스피너와 겹쳐 이중 깜빡임 | 내용 교체 페이드는 **성공 결과에만** 건다. 로딩 상태 전환에는 걸지 않는다 |
| 다크·라이트 테마 전환 | 테마 토글에 전환을 걸면 전체 화면이 200ms 동안 물결친다 — **테마 전환에는 모션을 넣지 않는다** |
| 터미널(xterm) | 자체 렌더러를 가진 캔버스다. 도크 프레임 바깥에만 모션을 두고 내부는 건드리지 않는다 |

## 테스트

- **순수 단위(정합 게이트)**: CSS 전수 검사로 **레이아웃 속성에 transition/animation이 걸리지 않았는지** 확인한다(`height`·`width`·`top`·`left`·`right`·`bottom`·`margin`·`padding`·`flex-basis`). 현재 0건이고 이 규칙이 이번 에픽의 최대 위험을 막는 안전망이다. `grid-template-rows`는 **의도된 예외**로 허용 목록에 둔다.
- **순수 단위**: 모션 토큰이 정의돼 있고 `--motion-slow`가 240ms를 넘지 않는지(느려지는 방향의 회귀 차단).
- **E2E**: ① `prefers-reduced-motion: reduce`를 강제한 창에서 주요 흐름이 그대로 동작하는지(Playwright `colorScheme`처럼 `reducedMotion` 옵션 사용) ② 커밋 상세 슬롯 열림/닫힘 후 우측 열 배치가 이전과 같은지(grid 전환 무회귀) ③ 기존 106건 전건.
- **실측 보고**: 상세 슬롯 열림 중 프레임 드랍, 파일 5000개 저장소에서 행 호버 전환의 비용.
- **스크린샷**: 모션은 정지 이미지로 안 보인다 — 대신 **열림 중간 프레임**을 캡처해 전환이 실제로 일어나는지 보인다.

## 범위 밖 (후속)

퇴장 애니메이션, 드래그 리사이즈 관성, 스크롤 앵커링·부드러운 스크롤, 목록 재정렬 FLIP, View Transitions 재검토, 모션 강도 사용자 설정.
