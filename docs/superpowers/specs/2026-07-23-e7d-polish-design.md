# E7d — 마무리 묶음(폴리시) 설계

2026-07-23 브레인스토밍 확정본. E7a·E7b·E7c 3에픽의 최우선 후속 노트에서 7건을 선별한 안정화 라운드(E6b 관례). 사용자 확정: 7건 그대로 / 테마는 설정으로 **완전 이관** / 화면 유지는 **재조회 가능한 것 전부**.

## 항목과 설계

### ① 충돌 시 [변경] 탭 자동 전환 (E7a 최우선 후속)

- 신호: 충돌 파일 개수(status.changes의 conflicted)가 **0 → 1+ 로 바뀌는 전이**. merge·pull·rebase·cherry-pick·revert·stash pop 모두 같은 신호로 잡힌다(유발 경로 무관).
- 동작: 좌측 탭을 'changes'로 전환. **전이 시 1회만** — 이후 사용자가 다른 탭으로 가는 것을 다시 막지 않는다. 이미 변경 탭이면 no-op.
- 구현 위치: App의 effect(충돌 개수 rising edge 감지). store 무변.

### ② 깨진 쉘 안내 (E7b 최우선 후속)

- 문제: $SHELL이 깨져 있으면 pty 스폰은 성공하고 자식이 즉시 죽어(onExit) 탭에 "(종료)"만 남는다 — 침묵 실패.
- 판정: 세션이 **출력을 한 번도 보내지 않고 exit** — 정상 쉘은 프롬프트라도 찍는다. 세션별 수신 플래그(renderer 훅)로 판정.
- 동작: 도크 에러 줄(기존 terminal-dock__error 슬롯)에 "쉘이 바로 종료됐어요. 로그인 쉘($SHELL) 설정을 확인해 주세요." 표시. 탭 "(종료)" 표기는 그대로.
- exit code 무관(0이어도 무출력 즉시 종료면 안내) — 판정 함수는 순수 함수로 분리해 단위 테스트.

### ③ 터미널 테마 연동 (E7b 후속)

- xterm 팔레트를 **라이트/다크 2벌**로 정의(디자인 토큰과 어울리는 값 — 다크는 기존 TERMINAL_THEME 유지, 라이트 신규). 배경·전경·커서·선택 영역 포함.
- 앱 테마 상태를 App → TerminalDock → useTerminalSessions로 내려보내고, 테마 전환 시 **열린 세션 전부** `terminal.options.theme` 런타임 교체(xterm 지원 — 플랜 사전 실측으로 확인).
- 새 세션은 현재 테마 팔레트로 생성.

### ④ 새 브랜치 동시 생성 워크트리 (E7c 후속)

- AddWorktreeDialog에 모드 라디오 2지: **기존 실험 공간 펼치기**(현행 select) / **새로 만들면서 펼치기**(이름 입력).
- 새 모드: 이름 입력 → 경로 자동 제안이 이름을 따라감(suggestWorktreePath 재사용, pathEdited 관례 동일) → `git worktree add -b <이름> <경로>` (**지금 위치(HEAD) 기준** — 기준 선택은 YAGNI).
- 엔진: `worktrees.add(path, branch)`에 신규 브랜치 플래그 확장(시그니처는 플랜에서 확정 — options 객체 권장). 거부 매핑(플랜 사전 실측): 잘못된 이름(check-ref-format 위반)·이미 있는 브랜치 이름 → 친절 메시지. 기존 매핑(사용 중 브랜치·기존 경로)은 유지.
- IPC·preload·store 시그니처 동반 확장.

### ⑤ 보던 화면 유지 — externalRefresh 재조회 (E7b 후속)

- 원칙: **새로고침의 의미는 '최신화'지 '닫기'가 아니다.** 외부 변경 자동 갱신이 CLEAR_SELECTIONS로 다 닫는 대신, 재조회 가능한 선택은 재조회해 유지한다.
- 유지 대상과 재조회 키:
  | 선택 | 키 | 대상이 사라졌으면 |
  | --- | --- | --- |
  | 파일 diff(selected/diff/diffLabel) | 경로+staged | 그 파일이 더는 해당 변경이 아니면 닫기 |
  | 커밋 상세(commitDetail·commitFile) | 해시(+파일 경로) | 커밋이 사라졌으면(재조회 실패) 닫기, 파일이 상세에 없으면 파일만 닫기 |
  | 비교 뷰(branchCompare) | 브랜치 이름 | 브랜치가 사라졌으면 닫기 |
  | 충돌 뷰(conflictFile) | 경로 (E7b 기존) | 기존 동작 유지 |
- 리뷰 상세(pullDetail)는 네트워크 상태라 git 갱신과 무관 — 현행 유지.
- **수동 새로고침(refresh)도 같은 의미론으로 통일**한다(두 갱신 경로의 일관성).
- 재조회 실패는 조용히 닫기(에러 배너 없음 — 외부 변경으로 대상이 사라진 것은 오류가 아니다).

### ⑥ 워크트리 자잘 2건 (E7c 품질 리뷰 Minor)

- `revealWorktree`를 guard(busy 직렬화)에서 분리 — 읽기 전용·즉발 동작이라 언제나 동작. 실패만 에러 배너(try/catch + set).
- prunable 워크트리의 "앱에서 열기" 방어 심층: main의 openPath 검증에서 prunable이면 "폴더가 사라진 워크트리예요. 지우기로 정리해 주세요." 친절 거부(현행은 rev-parse ENOENT 원어 노출). UI 비활성은 기존 그대로(1차 방어).

### ⑦ 테마 설정 이관 (E7c 후속 — 설정 카테고리 확장 1호)

- 헤더의 어둡게/밝게 토글 버튼 **제거**(헤더 단순화).
- SettingsDialog 카테고리 [일반 | 테마] 2개 — 카테고리 전환 상태가 이번에 처음 실사용된다(현재는 "일반" 고정 표시). 선택 카테고리 로컬 상태·사이드바 활성 표시.
- [테마] 내용: 라디오 2지(밝게/어둡게), 즉시 적용·저장 — 기존 theme.ts(applyTheme·영속)를 그대로 재사용. App의 테마 상태 소유는 무변(설정 다이얼로그가 변경을 위임받을 뿐).
- E2E 갱신: 기존 테마 토글 E2E(헤더 버튼 경유)는 설정 경유로 재작성.

## 에러·엣지

| 상황 | 처리 |
| --- | --- |
| 새 브랜치 이름이 규칙 위반/중복 | 엔진 stderr 매핑 친절 거부(다이얼로그 인라인 에러·입력 보존) |
| 무출력 exit인데 정상 상황(예: 즉시 exit 명령) | v1 수용 — 첫 세션 스폰 판정이므로 사용자가 명령을 칠 새 없음(자연 발생 없음) |
| 자동 갱신 재조회 중 또 외부 변경 | 디바운스(300ms)+억제 창(800ms)이 폭주를 이미 묶는다 — 추가 장치 없음 |
| 충돌 전이 감지 중 탭이 이미 changes | no-op (전환 안 함) |
| 테마 전환 시 터미널 세션 0개 | no-op — 다음 세션부터 새 팔레트 |

## 테스트

- **단위**: ② 판정 순수 함수(무출력 exit → 안내, 출력 후 exit → 무안내), ③ 팔레트 매핑(라이트/다크 키 완전성), ⑤ 재조회 분기(유지/닫기 결정 — 순수화 가능한 부분), ④ 엔진 add 신규 브랜치(성공·이름 위반·중복 — 실제 git 픽스처), ⑥ openPath prunable 거부. sanitize류 무변.
- **E2E**: ① merge 충돌 유발 → 탭 자동 전환, ③ 설정에서 테마 변경 → 터미널 배경색 실측(xterm 인라인 스타일), ④ 새 브랜치 모드 생성 → `git worktree list`+`branch` 검증, ⑤ 터미널(외부) 커밋 후 커밋 상세 유지, ⑦ 설정 경유 테마 변경(기존 헤더 토글 E2E 재작성 포함).
- **플랜 사전 실측**: xterm 런타임 테마 교체 동작, `worktree add -b` 거부 stderr 문구(위반 이름·중복 이름), 무출력 exit 재현(GIT_GUI_E2E용 깨진 SHELL env), externalRefresh 재조회 키의 현행 CLEAR_SELECTIONS 필드 전수 대조.

## 범위 밖 (후속)

- 워크트리별 dirty 배지, xterm 검색·링크·분할, 원격 새로고침(fetch --all — 원격 심화 방향으로), 브랜치 목록 가상화, 설정 검색·프로필 카테고리, 새 워크트리 기준 커밋 선택(-b의 base 인자)
