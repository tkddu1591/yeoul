# E10 — 외부 변경 감지(워킹트리 감시 + 포커스 갱신) 설계

2026-07-29 사용자 제보: "diff가 있는 상태에서 강제로 롤백하고 git gui를 봐도 업데이트가 안 된다. 변경 없다고 떠야 하는데 변경되었다고 뜨고, 새 파일 만든 것도 다 지웠는데 있는 것처럼 뜨고, 조금 있다가 업데이트되는데 반응이 너무 느리다."

## 진단 (실측)

**느린 게 아니라 없는 기능이다.** 앱은 `.git`만 감시하고 워킹트리는 전혀 보지 않는다(`repo-watcher.ts:19` — `watch(gitDir, { recursive: true })`).

`.git` 이벤트 발생 여부 실측(임시 저장소, `fs.watch` 직접 계측):

| 시나리오 | `.git` 이벤트 |
| --- | --- |
| 추적 안 된 새 파일 생성 | **0건** |
| 그 파일 삭제 | **0건** |
| 추적 파일 수정 | **0건** |
| `git checkout -- <file>` | 3건(`index.lock`·`index`×2), **41ms 내** |

즉 **파일 내용만 바뀌는 변화는 앱에 도달할 경로가 없다.** 사용자 확인: 롤백은 **에디터의 되돌리기**였다 — 순수 워킹트리 쓰기라 이벤트 0건이 정확히 맞다.

"조금 있다가 업데이트"의 정체는 **10분 자동 페치**(`App.tsx:308`, `setInterval(…, 600_000)`)다. 그 외 갱신 경로는 수동 새로고침과 앱 내 액션뿐이고, **창 포커스 갱신은 존재하지 않는다**(전수 grep 0건).

## 폭풍 위험 실측 (설계를 정한 근거)

워킹트리 루트를 재귀 감시했을 때:

| 상황 | 이벤트 |
| --- | --- |
| 유휴 3초 | **0건** |
| 소스 1개 touch | **1건** |
| `pnpm --filter @git-gui/desktop build` 1회 | **209건** (전부 `apps/…/out/` — gitignore 대상) |

`git status --porcelain=v2`는 이 저장소에서 **20~100ms**. 209건이 디바운스로 1회 재조회에 합쳐지므로 비용은 무시할 만하다. **결론: `.gitignore` 파싱·무시 엔진은 필요 없다.** 과설계다. 진짜 위험은 폭풍 자체가 아니라 **연속 변경 중 트레일링 디바운스가 굶어 영원히 안 fire되는 것**이다(개발 서버가 계속 쓰는 상황).

## ① 워킹트리 감시

- 저장소 **루트**를 `recursive: true`로 감시한다. 기존 `.git` 감시는 그대로 둔다(둘은 목적이 다르다 — `.git`은 HEAD·refs·상태 마커, 워킹트리는 파일 내용).
- **`.git/`로 시작하는 경로는 버린다** — 이미 전용 감시가 있고, 중복 발화는 낭비다. 링크드 워크트리의 `.git`은 파일이라 이 규칙이 그 파일 1건도 걸러 준다.
- **무시 목록을 두지 않는다.** 실측상 디바운스가 흡수하고, 무시 규칙은 `.gitignore` 의미론을 반쯤 흉내 내다 틀리는 쪽이 더 위험하다. 이 판단의 근거(209건/1회)를 코드 주석에 남긴다.

## ② 굶지 않는 디바운스

기존 `createTrailingDebounce(300ms)`는 hit이 계속 오면 영원히 fire하지 않는다. **최대 대기(max-wait)를 더한다**: 첫 hit로부터 `MAX_WAIT_MS`(2000)가 지나면 조용해지길 기다리지 않고 발화한다. 기존 `.git` 감시도 같은 함수를 쓰므로 함께 개선된다.

순수 함수라 단위 테스트로 덮는다 — 이 저장소는 타이머 로직을 `watch-filter.ts`에 순수하게 두는 관례가 있다.

## ③ 포커스 갱신

창이 다시 활성화되면 재조회한다. 두 경로가 각각 필요하다:

- **감시가 잡지 못하는 잔여**를 메운다(감시 실패·`fs.watch` 에러로 감시가 죽은 경우 — `repo-watcher.ts:24`가 조용히 닫는다).
- 사용자가 다른 앱에서 작업하다 돌아오는 지배적 패턴에 즉답한다.

main의 `BrowserWindow`가 `focus`를 받으면 renderer로 push한다(창 상태는 main이 정본 — 렌더러 `window.onfocus`는 창이 숨김·백그라운드일 때 신뢰도가 낮고 E2E 숨김 창에서 안 뜬다). 렌더러는 기존 `externalRefresh`를 그대로 부른다.

## ④ 자기 꼬리 억제와의 관계

`externalRefresh`는 마지막 guard 종료 후 `WATCH_SUPPRESS_MS`(800) 안이면 건너뛴다. 워킹트리 감시가 붙으면 **앱 자신의 워킹트리 쓰기**(변경 취소·병합·스태시 꺼내기)도 이벤트를 낳는다. 800ms로 부족한 긴 작업이 있을 수 있으나, 억제를 벗어나 한 번 더 재조회하는 것은 **무해**(같은 결과를 다시 그릴 뿐)하므로 값을 바꾸지 않는다. 포커스 갱신은 억제 창을 **무시한다** — 사용자가 명시적으로 돌아온 순간이라 최신화가 우선이다.

## 에러·엣지

| 상황 | 처리 |
| --- | --- |
| 저장소 루트가 사라짐(폴더 삭제) | `fs.watch` error → 조용히 닫는다(기존 `.git` 감시 관례 그대로) |
| 링크드 워크트리 | 루트는 실제 폴더라 그대로 감시 가능. `.git`은 파일이며 `.git/` 접두 규칙이 거른다 |
| 아주 큰 저장소 | FSEvents는 커널 측이라 등록 비용이 낮다(실측 유휴 0건). 재조회는 디바운스로 1회 |
| 감시 중 저장소 전환 | 기존 `stopWatching?.()` 교체 규칙을 워킹트리 감시에도 동일 적용 |
| 창이 숨김인 E2E | 포커스 push는 main의 `focus` 이벤트라 숨김 창에서는 안 온다 — E2E는 감시 경로로 검증하고, 포커스는 단위(순수 함수)와 수동 확인 |

## 테스트

- **순수 단위**: max-wait 디바운스(연속 hit이 `MAX_WAIT_MS`를 넘으면 발화, 조용해지면 즉시 발화, dispose 후 무발화), `.git/` 접두 배제 필터.
- **E2E**: ① 앱 밖에서 **추적 안 된 파일을 만들면** 변경 목록에 나타난다 ② **그 파일을 지우면** 사라진다 ③ 앱 밖에서 **추적 파일을 수정하면** 변경으로 뜨고, 되돌리면 사라진다 — 셋 다 수동 새로고침 없이. (E10 이전에는 셋 다 영원히 안 뜬다 — 회귀 검출력이 확실하다.)
- **무회귀**: 기존 `.git` 감시 E2E 전건, 자기 꼬리 억제(앱 내 작업 직후 화면이 되돌아가지 않는지).
- **실측 보고**: 빌드 1회(209 이벤트) 중 재조회가 **몇 번** 일어나는지 — 1~2회여야 한다.

## 범위 밖 (후속)

`.gitignore` 인식 무시 규칙, 감시 실패 시 사용자 알림, 폴링 대체 경로, 원격 변경 감지 주기 단축, 감시 대상 사용자 설정.
