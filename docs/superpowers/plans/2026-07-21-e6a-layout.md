**Goal:** 사용자 제안대로 3열을 재배치한다 — 좌측은 변경 목록+저장 폼(하단 푸터), 중앙은 diff·충돌 뷰 전용(세로 전체), 우측은 평소 트리 전체이고 **커밋 클릭 시에만 하단에 상세가 열린다**(트리는 계속 보이며 선택 행 하이라이트). 함께 두 가지 근본 문제를 해소한다: ① E2E 실행 때마다 Electron 창이 사용자 작업 화면을 가리는 문제(숨김 창 실행 — 실측 42건 통과), ② 고정 340/360px 열이 960px 창에서 중앙을 ~200px로 짜부라뜨리던 문제(E2 후속 노트 — 창 폭 반응형 열 계산으로 **960px 창 중앙 ≥ 380px 보장**).

**Architecture:** store 상태(commitDetail·pullDetail·CLEAR_SELECTIONS)는 **한 줄도 바꾸지 않고 렌더 위치만 바꾼다**. App.tsx의 우측 3분기(리뷰 상세/커밋 상세/트리)를 "리뷰 상세(전체 전환 유지 — 대화형, 사용자 동의) vs 트리+조건부 하단 슬롯"으로 재구성하고, CommitDetailPanel을 하단 45% 슬롯에서 그대로 재사용한다(보관함 미리보기 shelfPreview 분기 포함, testid 전부 유지). 열 폭은 기존 inline grid 스타일 관례를 따라 순수 함수 `computeColumns(viewportWidth, rightWidth)`(column-resize.ts)가 좌·우를 함께 계산한다 — 우선순위: 중앙 ≥ 380 > 사용자 우측 폭 > 좌측 기본 380. E2E 창 비간섭은 main/index.ts에서 `GIT_GUI_E2E_REPO` env 게이트(+`!app.isPackaged`, 기존 관례)로 `show: false`+`backgroundThrottling: false`+`app.dock?.hide()` — 프로덕션 동작 무변.

**Tech Stack:** 기존 그대로 — TypeScript, Electron(main/preload/renderer), zustand, vitest, Playwright(Electron E2E).

**기준 커밋:** `feature/e6a-layout` = `d9adac1`. 기준선 실측: 단위 **348 tests**(27 files, `pnpm test` 실행 — 348 passed), E2E **42**(smoke 36 + hosting 6, `grep -c "^test("` 실측).

export const LEFT_COLUMN_DEFAULT = 380
/** 좌측(변경 목록+저장 폼) 하한 — 이 아래로는 체크박스·버튼 줄이 붕괴한다 */
export const LEFT_COLUMN_MIN = 260
/** 중앙(diff·충돌 뷰) 최소 보장 폭 — 960px 최소 창에서도 지킨다 (E2 후속 노트 해소) */
export const CENTER_MIN = 380
/** 그리드 고정 소모 폭 — main 좌우 패딩 20×2 + 열 간 gap 16×3 + 리사이저 6 (layout.css와 짝) */
const MAIN_CHROME = 94
/** 중앙 보장이 우측 클램프 하한(260)과 충돌할 때 우측이 내려가는 마지막 바닥 */
const RIGHT_COLUMN_FLOOR = 200

/**
 * 창 폭·저장된 우측 폭 → 실제 좌·우 열 폭 (E6a 반응형).
 * 우선순위: ① 중앙 ≥ CENTER_MIN ② 사용자가 정한 우측 폭 ③ 좌측 기본 폭.
 * 좁아지면 좌측이 먼저 260까지 줄고, 그래도 모자라면 우측이 클램프 하한 아래로 함께 줄어든다.
 * (960px 창: 좌 260·우 226·중앙 380 — 검산은 플랜 실측 표)
 */
export function computeColumns(
  viewportWidth: number,
  storedRight: number,
): { left: number; right: number } {
  const budget = viewportWidth - MAIN_CHROME - CENTER_MIN
  let right = clampRightWidth(storedRight, viewportWidth)
  const left = Math.min(LEFT_COLUMN_DEFAULT, Math.max(LEFT_COLUMN_MIN, budget - right))
  if (budget - right < LEFT_COLUMN_MIN) {
    right = Math.max(RIGHT_COLUMN_FLOOR, budget - LEFT_COLUMN_MIN)
  }
  return { left, right }
}

3. **`<CommitForm` 앵커 중복 위험** — 좌측 이동 후 같은 들여쓰기 사본이 생겨 앵커가 2회 매칭됨. Task 3 스텝 순서를 "중앙 제거(Step 5) → 좌측 래핑(Step 6)"으로 고정하고 경고 병기.
4. **960px 좌측 260px에서 bulk 버튼 줄 오버플로** — "모두 선택+변경 취소+선택 올리기"가 ~270px로 260px 열을 넘침(계산 검토). `.file-list__bulk`에 flex-wrap 추가(Task 3 Step 8) + 스크린샷 육안 항목에 편입.
5. **주의 ③(축소 높이 가상 스크롤) 검증 누락** — E2E '스크롤 끝에서…'를 상세 열린 상태로 강화(Task 4 Step 6-e)해 트리 높이 축소 상태의 onLoadMore를 게이트에 편입.
6. **숨김 창 스크린샷의 공허 통과 위험** — 흰 화면이어도 파일은 생긴다. 실측 프로브에서 바이트 하한+육안(완전한 UI 렌더 확인)으로 검증했고, 첫 스모크에 `isVisible() === false` 단언을 넣어 회귀를 가드(Task 1 Step 2).
