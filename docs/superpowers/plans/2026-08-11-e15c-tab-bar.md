```ts
interface CreatedWindow {
  window: BaseWindow
  view: WebContentsView
}

function createWindow(seed: WindowSeed = { repoPath: null, layout: {} }): CreatedWindow {
  const window = new BaseWindow({
    width: 1200,
    height: 800,
    minWidth: 960,
    minHeight: 600,
    title: 'Git GUI',
    // E7f 한 줄 타이틀바 → E15c: BrowserWindow가 아니라 BaseWindow지만 같은 옵션을 받는다
    // (실측: BaseWindowConstructorOptions에 titleBarStyle:231·trafficLightPosition:237).
    // E15b에서 네이티브 탭을 막았던 hidden이 여기서는 아무것도 안 막는다 — 탭은 우리가 그린다
    ...(process.platform === 'darwin'
      ? { titleBarStyle: 'hidden' as const, trafficLightPosition: { x: 20, y: 22 } }
      : {}),
    backgroundColor: resolveBackgroundColor(),
    show: false,
  })

  const view = createRepoView(seed)
  window.contentView.addChildView(view)
  fitViewToWindow(window, view)
  // 창 리사이즈마다 뷰를 창 크기에 맞춘다 — BrowserWindow 시절엔 공짜였던 것
  window.on('resize', () => fitViewToWindow(window, view))

  // ⚠️ ready-to-show는 BrowserWindow의 이벤트다 — BaseWindow에는 없다.
  // 뷰의 webContents가 첫 페인트를 마치는 신호로 바꾼다. did-finish-load는 페인트 이전이라
  // 흰 화면이 보일 수 있다(E13이 없앤 것) — 실측으로 맞는 신호를 찾는다:
  // 후보 ① view.webContents.once('did-finish-load') ② 'dom-ready' ③ paint 관련 이벤트.
  // E13의 판정 기준(창이 드러날 때 흰 배경이 한 프레임도 안 보인다)을 GIT_GUI_E2E_SHOW=1로
  // 눈으로 확인하고, 무엇을 골랐고 왜인지 보고한다
  view.webContents.once('did-finish-load', () => {
    if (!isE2E || isE2EShow) window.show()
  })

  registry.add(view.webContents.id, { repoPath: seed.repoPath, layout: seed.layout })
  const viewId = view.webContents.id
  window.on('closed', () => registry.remove(viewId))
  return { window, view }
}

/** 뷰 하나가 창 콘텐츠 전체를 덮는다 — Task 5에서 탭이 늘어도 이 함수는 그대로다(전부 전체 크기,
 * 보이는 것 하나) */
function fitViewToWindow(window: BaseWindow, view: WebContentsView): void {
  const { width, height } = window.getContentBounds()
  view.setBounds({ x: 0, y: 0, width, height })
}

function createRepoView(seed: WindowSeed): WebContentsView {
  const view = new WebContentsView({
    webPreferences: {
      preload: join(__dirname, '../preload/index.js'),
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
      backgroundThrottling: !isE2E,
    },
  })
  // 이 뷰는 preload로 git 조작 API를 갖는 특권 표면이다 — 외부 네비게이션과 새 창을 차단한다
  view.webContents.setWindowOpenHandler(() => ({ action: 'deny' }))
  view.webContents.on('will-navigate', (event) => event.preventDefault())
  if (!app.isPackaged && process.env.ELECTRON_RENDERER_URL) {
    void view.webContents.loadURL(process.env.ELECTRON_RENDERER_URL)
  } else {
    void view.webContents.loadFile(join(__dirname, '../renderer/index.html'))
  }
  return view
}
```

  layout: WindowLayout
}
export interface WindowRegistry {
  addWindow(windowId: number, layout: WindowLayout): void
  removeWindow(windowId: number): void
  getWindow(windowId: number): WindowState | undefined
  /** 탭을 창에 더한다 — index는 생략 시 끝. 같은 탭을 두 창에 넣으면 throw(프로그래밍 오류다) */

## 실행 중 실측 정정 (컨트롤러)

### Task 1 (관문 통과 — 150/150)

- **Playwright는 뷰를 그대로 잡는다**: `firstWindow()` = 뷰의 webContents(page로 정상 — testid·screenshot·harness close 훅 전부), `app.windows()` = 1. **`BrowserWindow.getAllWindows()`는 0** — BaseWindow는 그 목록에 안 잡힌다. E2E의 `app.evaluate` 5곳이 그걸 쓰고 있어 `BaseWindow`로 국소 수정했다(플랜 Files 목록에 `smoke.spec.ts`가 빠져 있었다).
- **창↔뷰 수명이 양방향 모두 끊어져 있다** (BrowserWindow와 다름 — 각각 단독 실측). ① 창을 닫아도 뷰 webContents가 파괴되지 않는다(`destroyed` 미발화) → `closed`에서 명시적 `view.webContents.close()`. 없으면 `git-handlers`·`terminal-handlers`의 `once('destroyed')` 정리(감시·pty)가 영영 안 돈다. ② webContents가 먼저 파괴돼도 창이 안 닫힌다 → 빈 창이 레지스트리에 남아 복원이 유령 창을 만든다(첫 실행 E2E 2건이 정확히 이 모양). `view.webContents.once('destroyed', () => window.close())` + `isDestroyed()` 가드(상호 재귀 차단). **플랜 스니펫에는 이 두 배선이 없었다.** Task 3의 "destroy 계열 실측"이 사실상 여기로 앞당겨졌다.
- **첫 페인트 신호는 WebContentsView에 노출되지 않는다**(webContents `'paint'`는 오프스크린 전용). `did-finish-load` + **두 겹 배경색**(창 `backgroundColor` + `view.setBackgroundColor()`)으로 흰 프레임을 구조적으로 막았다 — 뷰 배킹 기본색이 흰색이라 창 배경만으로는 부족하다.
- 스니펫의 `createRepoView(seed)`는 `seed` 미사용으로 lint에 걸린다 — 탭별 씨앗이 생기는 태스크에서 다시 붙인다.

### Task 6 실측 정정

- **`mode: 'new-tab' | 'this-tab'` 기본 설계를 버렸다** (플랜이 허용한 편차). 'this-tab'의 "갈아탄다"는 main이 실행할 수 없다 — E15a가 스토어 `openRepository`에 쌓은 상태 유출 정리·최근 목록 갱신·`forgetRepoIfCertain`이 전부 렌더러에 있다. 그래서 mode를 받은 `tabs:open`은 중복이 아닐 때 "내가 안 했으니 네가 해라"를 돌려줘야 하는 절반짜리 open이 된다. 대신 **판정 IPC `tabs:show-existing`**(있으면 데려가고 true, 없으면 아무것도 안 하고 false)을 갈라, false를 받은 렌더러가 기존 경로로 잇는다 — 판정은 정본(main 레지스트리), 실행은 기존 코드 그대로.
- **판정/실행 분리 경합은 실제 문제가 아니라고 판단** (근거 셋, `tabs:show-existing` 핸들러 주석): ① 틈이 IPC 왕복 크기인데 끼어들려면 그 안에 **다른 창에서의 사용자 조작**이 필요하다 ② 같은 모양의 틈이 `tabs:open`·`window:open` 안에도 이미 있다(`await openRepoPath` 동안 레지스트리가 변한다) — 분리가 새 종류의 경합을 만들지 않는다 ③ 져도 깨지는 값이 없다(감시·pty·설정 전부 탭 단위라 두 탭이 같은 저장소를 봐도 각자 정합, 한쪽이 떠나면 저절로 풀린다).
- **"데려간다" 실행을 `revealExistingTab` 하나로 모았다** — 창 앞으로(show+focus)+`setActiveTab`+가시성 전환을 세 진입점(`tabs:open`·`window:open`·`tabs:show-existing`)이 공유한다. 규칙 하나의 실행이 진입점마다 갈라지는 것을 구조로 막는다.
